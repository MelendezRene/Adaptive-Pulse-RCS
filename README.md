# Adaptive Pulse RCS

Universal automatic pulse controller for Kerbal Space Program 1.12.x.

## Beta 1 — v0.3.0-b1

This is the first beta baseline for the project.

Adaptive Pulse RCS is designed to make RCS behave more like an automatically managed spacecraft attitude-control system instead of simply holding thrusters on whenever a control input exists.

The player does **not** set pulse duration manually.

## What Beta 1 does automatically

- Detects every `ModuleRCS` / `ModuleRCSFX` on the active vessel.
- Inspects each active `thrusterTransform`.
- Uses the KSP RCS direction convention:
  - `useZaxis ? -transform.forward : transform.up`
- Measures each nozzle's position relative to the current vessel center of mass.
- Calculates force and torque contribution for each nozzle.
- Accounts for the module's enabled pitch, yaw, roll and translation axes.
- Reads control demand generated by the player, stock SAS, MechJeb or other systems using normal `FlightCtrlState`.
- Selects only RCS modules that can contribute in the requested direction.
- Estimates available translational acceleration from thrust and vessel mass.
- Estimates rotational authority from torque, vessel mass and characteristic radius.
- Calculates pulse length automatically.
- Uses shorter pulses for low demand and larger pulses for stronger corrections.
- Allows continuous firing at very high demand.
- Uses a deadband so the RCS is not constantly chattering.
- Recalculates RCS geometry when vessel mass changes significantly.
- Re-scans after vessel modification, docking/staging-related vessel changes and manual refresh.

## Important Beta 1 limitation

KSP's stock `ModuleRCS` exposes the individual nozzle transforms for analysis, but does not provide a safe public interface for independently switching individual transforms inside the same module.

Therefore Beta 1:

1. models **each nozzle individually** for force/torque calculations;
2. chooses useful RCS **modules** based on those calculations;
3. gates firing at `ModuleRCS` level.

This keeps the beta compatible with stock KSP behavior and avoids modifying RealFuels/RO internals.

A later development branch can investigate true per-transform actuation if it can be done without destabilizing `ModuleRCS`.

## Compatibility target

- KSP 1.12.x
- Realism Overhaul
- RealFuels
- ModuleRCS / ModuleRCSFX
- MechJeb2
- stock SAS
- kOS or other systems generating normal flight-control inputs

Adaptive Pulse RCS does **not** replace those guidance systems. They continue deciding *where the spacecraft should move*. This plugin decides *how the available RCS should pulse*.

## Realism Overhaul / RealFuels

The plugin does not change:

- propellant type;
- mixture ratio;
- tank configuration;
- feed system;
- Isp;
- configured RCS thrust.

Those remain controlled by the installed part configuration and RO/RealFuels.

Adaptive Pulse RCS uses the RCS authority that actually exists on the vessel.

## Controls

- Stock RCS action group: master hardware enable.
- `Alt + P`: show/hide Adaptive Pulse RCS window.
- **Automatic adaptive pulse control**: enables/disables the controller.
- **Re-scan vessel**: manually rebuilds the RCS authority model.
- **Restore stock RCS**: disables Adaptive Pulse RCS and restores the module enable states.

## Source layout

- `src/AdaptivePulseRCS/` — C# source and project.
- `GameData/AdaptivePulseRCS/` — installable mod structure.
- `lib/` — local KSP DLL references for building; DLLs are intentionally not committed.

## Local build

Copy these KSP managed DLLs into `lib/`:

- `Assembly-CSharp.dll`
- `UnityEngine.dll`
- `UnityEngine.CoreModule.dll`
- `UnityEngine.IMGUIModule.dll`

Then run:

```powershell
./build.ps1
```

Expected output:

`GameData/AdaptivePulseRCS/Plugins/AdaptivePulseRCS.dll`

## Beta test priorities

For Beta 1, testing should focus on:

- correct detection of RCS modules and transforms;
- correct pitch/yaw/roll direction selection;
- correct X/Y/Z translation selection;
- pulse duration on very small versus very large RCS systems;
- behavior on high-mass RO spacecraft;
- behavior during SAS attitude hold;
- behavior while MechJeb commands attitude;
- behavior after staging/docking;
- whether any RCS module gets left disabled after turning the controller off.
